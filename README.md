# HackAlem AI — Intelligent Procurement Recommendations

Система поддержки закупщика, которая анализирует входные данные по товарам и формирует рекомендации по объёму заказа для каждого поставщика.

Проект разрабатывается в рамках хакатона **HackAlem AI**.

## Задача

Закупщику необходимо быстро понимать:

* какие товары требуют пополнения;
* сколько единиц рекомендуется заказать;
* насколько срочно требуется заказ;
* сколько товара уже находится в пути;
* почему система рекомендует именно такое количество.

Система обрабатывает входные CSV-файлы и формирует структурированный список рекомендаций, сгруппированный по поставщикам.

## Основной сценарий

1. Пользователь загружает CSV-файлы через интерфейс.
2. Система определяет и обрабатывает необходимые данные.
3. Расчётный модуль формирует рекомендации по закупке.
4. Интерфейс показывает результат по каждому поставщику.
5. Менеджер проверяет рекомендации и вручную утверждает нужные позиции.
6. Отфильтрованный результат можно экспортировать в CSV/Excel.

Заказы **не отправляются поставщикам автоматически** — финальное решение остаётся за закупщиком.

## Интерфейс

Дашборд содержит:

* загрузку файлов через drag & drop или кнопку;
* отображение статуса обработки;
* сообщения об ошибках по конкретным поставщикам;
* таблицу рекомендаций, сгруппированную по поставщикам;
* поиск по артикулу и названию;
* фильтрацию по поставщику и срочности;
* ручное подтверждение рекомендуемых заказов;
* экспорт текущей выборки.

### Основные поля рекомендации

* `sku` — артикул;
* `name` — наименование;
* `category` — категория;
* `current_stock` — текущий остаток;
* `in_transit_qty` — количество товара в пути;
* `recommended_qty` — рекомендуемое количество заказа;
* `urgency` — срочность;
* `reason` — объяснение рекомендации.

Допустимые значения `urgency`:

* `critical`
* `soon`
* `planned`

Формат этих полей используется как контракт между расчётным модулем и интерфейсом.

## Архитектура

Проект условно разделён на несколько частей:

* **Data / Calculation** — обработка входных данных и расчёт рекомендуемого заказа;
* **API / Integration** — передача результатов расчёта в интерфейс;
* **Dashboard / Frontend** — отображение рекомендаций и взаимодействие пользователя с системой.

Компоненты разрабатываются параллельно участниками команды и интегрируются через согласованный JSON-контракт.
