## Запуск мокового дашборда

UI реализован в `dashboard/` на HTML/CSS/JavaScript без сторонних зависимостей.
Из корня репозитория (сервер обслуживает только `dashboard/`):

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory dashboard
```

Открыть http://localhost:8000/. Требуется HTTP-сервер: загрузка JSON через
`file://` браузером не поддерживается. Поиск, фильтры, подтверждение отдельных
позиций и видимых позиций поставщика, просмотр причин и экспорт текущей
выборки в CSV работают локально. Для экспорта только подтверждённых включите
соответствующий фильтр. CSV содержит BOM и разделитель `;` для открытия в Excel.
Подтверждения сбрасываются при обновлении страницы; отправки заказов нет.
Загрузка CSV проверяет только расширение, непустой размер и лимит 10 МБ на файл.
Содержимое не разбирается и не отправляется: расчётный модуль ещё не подключён.
После выбора файлов показываются «Обработка…» и явно обозначенный пример ошибки
«Не хватает файла "Товар в пути" для IEK» независимо от выбранных файлов.

### Контракт для Человека 2

Используется предоставленная структура без изменений:
`{ "generated_at": "2026-09-23", "suppliers": [{ "supplier": "IEK", "items": […] }] }`.
Поставщики идентифицируются по `supplier`, SKU уникален внутри поставщика.
Дополнительные optional-поля в JSON не добавлены.
Все восемь полей рекомендации из README сохранены без переименования:
`sku`, `name`, `category`, `current_stock`, `in_transit_qty`, `recommended_qty`,
`urgency`, `reason`. Количества — неотрицательные числа, остальные поля —
непустые строки. `urgency` строго `critical`, `soon`, `planned`.
Новых полей внутри рекомендаций нет. Подтверждение хранится отдельно в UI;
`approved` добавляется только в экспорт CSV, не в JSON расчётного модуля.
Рекомендации и причины в моках вымышлены, не являются результатом расчёта.

```bash
node --test dashboard/tests/*.test.mjs

node --check dashboard/recommendations.mjs
```
