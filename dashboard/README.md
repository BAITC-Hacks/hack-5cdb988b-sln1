## Dashboard закупщика

Интерфейс на HTML/CSS/JavaScript без runtime-зависимостей и сборки.
До первого расчёта рекомендации пусты. Выбор файлов и drag & drop показывают
список; новый выбор заменяет список. Файлы можно убрать перед отправкой.
Кнопка «Загрузить и рассчитать» отправляет один синхронный запрос
`POST /api/upload`, `multipart/form-data`, с повторяющимся полем `files`.
Ограничения форматов и состава данных определяет существующий backend.

Dashboard должен обслуживаться с того же origin, где доступен `/api/upload`
(например, через существующий reverse proxy). Настройки backend не меняются.
Для просмотра только интерфейса можно запустить из корня репозитория:

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory dashboard
```

Открыть http://localhost:8000/. Этот статический сервер не предоставляет API:
кнопка расчёта получит HTTP-ошибку, пока `/api/upload` не доступен на том же origin.
Текущий backend также возвращает 501, если модуль парсера ещё не подключён;
его сообщение отображается пользователю. Mock backend и polling отсутствуют.

Ответ проверяется через `validateData`:
`{ generated_at, suppliers: [{ supplier, items: […] }], errors: [{ supplier, error }] }`.
Сохранены поля `sku`, `name`, `category`, `current_stock`, `in_transit_qty`,
`recommended_qty`, `urgency`, `reason`. Формат даты — `YYYY-MM-DD`.
Список `errors` необязателен для совместимости с прежними тестовыми данными.
Частичные ошибки отображаются отдельно от успешных результатов.
При ошибке HTTP/сети или некорректном ответе предыдущий расчёт сохраняется.
При новом корректном ответе результаты заменяются, подтверждения очищаются,
фильтр поставщика и «Только подтверждённые» сбрасываются. Поиск и срочность сохраняются.

Доступны поиск, фильтры, подтверждение строк и видимых позиций поставщика,
раскрываемые причины и экспорт текущей выборки в CSV (BOM, разделитель `;`).
Для экспорта подтверждённых позиций включите соответствующий фильтр.
Подтверждения локальны и сбрасываются при новом расчёте или обновлении страницы.
Заказы автоматически не отправляются.

`mock_recommendations.json` сохранён только как fixture существующих и новых
тестов; интерфейс его не загружает, demo fallback отсутствует.

## Проверки

Нужен Node.js 22.13+ (или совместимая более новая версия).
`jsdom` используется только в тестах, в браузер не поставляется.

```bash
npm ci --prefix dashboard
node --test dashboard/tests/*.test.mjs
npm run check --prefix dashboard
```

DOM-тесты проверяют выбор и удаление файлов, drag & drop, multipart-запрос,
загрузку до завершения чтения ответа, защиту от повторной отправки, обновление
поставщиков и подтверждений, ошибки HTTP/сети/JSON, частичные ошибки, фильтры,
explanation и экспорт. Сетевые ответы подставляются только внутри тестов.
